# Common-Garden

Automated segmentation and identity tracking of frailejones (plants) and their
pots across terraces over time. The segmentation stage detects every plant and
pot per image; the tracking stage maintains each instance's identity
(`bed_position`) across dates and flags appearances / disappearances.

Every script runs with **no arguments** — paths are set as constants at the top
of each file. Edit those constants if your layout differs.

## Structure

```
common-garden/
├── data/
│   ├── annotations/          # Label Studio exports (terrace_*.json) — you provide
│   ├── images/               # terrace photos — you provide
│   └── figs/                 # figures / IDA plots
├── datasets/                 # GENERATED by build_dataset.py
│   ├── obj1_final/           #   final held-out test (last date per terrace)
│   ├── obj1_forward/         #   forward-chaining CV folds
│   ├── obj2_loto/            #   leave-one-terrace-out CV folds
│   └── tracking/             #   tracking_ST*.json ground truth
├── modeling/
│   ├── build_dataset.py      # annotations + images -> datasets/ + id sidecars + tracking GT
│   ├── quick_train.py        # optional 5-epoch smoke test
│   ├── run_obj1_cv.py        # Objective 1 forward-chaining CV -> mean ± std
│   ├── cv_run.py             # Objective 2 LOTO CV -> mean ± std
│   ├── train_gpu.py          # final model trained on obj1_final
│   └── postprocess.py        # convex hulls + pot ellipses + centroids -> JSON
├── tracking/
│   └── matcher.py            # registration + Hungarian assignment -> IDF1 / ID-switches
├── outputs/                  # example deliverables (placeholder schema shown)
│   ├── postprocess/          #   per-image *.json (hull, ellipse, centroid) + overlays
│   └── tracking/             #   tracking_summary.csv, assignments_ST*.json, overlays
├── .gitignore
└── README.md
```

## Two objectives

- **Objective 1 (known terrace, predict future dates)** — forward-chaining CV:
  each fold trains on earlier rounds and validates on the next. Averaged over
  folds (`mean ± std`). The honest final number comes from `obj1_final`, the last
  date of each terrace, held out from all tuning.
- **Objective 2 (unseen terrace)** — leave-one-terrace-out CV: a whole terrace is
  held out for test, another for validation, never seen in training.

Cross-validation yields a **number**, not a model — the per-fold weights are
throwaway; only the aggregate is kept.

## Setup

```
pip install ultralytics opencv-python-headless scipy numpy
```

Drop your Label Studio JSON exports in `data/annotations/` and the matching
terrace photos in `data/images/`.

## Run order

```
python modeling/build_dataset.py     # 1. build folds + id sidecars + tracking GT
python modeling/quick_train.py       #    (optional smoke test — 5 epochs)
python modeling/run_obj1_cv.py       # 2. Objective 1 CV  -> mean ± std
python modeling/cv_run.py            # 3. Objective 2 LOTO -> mean ± std
python modeling/train_gpu.py         # 4. train final model on obj1_final
python modeling/postprocess.py       # 5. hulls + ellipses + centroids -> outputs/postprocess
python tracking/matcher.py           # 6. IDF1 / ID-switches -> outputs/tracking
```

Steps 2–3 report the metrics for the report; step 4 produces the one `best.pt`
that steps 5–6 consume.

## Outputs

`outputs/` holds **placeholder** examples showing the exact schema each stage
emits (real runs overwrite them):

- `outputs/postprocess/<image>.json` — per instance: `class`, `centroid`, and
  either `polygon` + `convexity_ratio_before` (plants) or `ellipse` (pots).
- `outputs/tracking/tracking_summary.csv` — per terrace IDF1, ID-switches,
  node-assignment accuracy, appearances / disappearances.
- `outputs/tracking/assignments_ST*.json` — per-date identity assignments.
